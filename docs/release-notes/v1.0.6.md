# musicdl 1.0.6

## English

- `lossless_first` now actually asks a source for lossless. When the policy is `lossless_first` and a candidate declares no tiers -- which is what this deployment's catalogue answers -- the download asks for FLAC instead of silently taking the `320k` default. Both the administration panel and the WeCom message path are wired this way.
- A requested tier is intent, never a claim about the source. The download report keeps the ask (`requested_quality`) apart from the delivered bytes (`actual_quality`), and the panel names the gap ("requested flac, got mp3") when a lossless request was answered with something smaller. Nothing is reported as lossless that the source did not actually serve, and a candidate's declared tiers are never rewritten to make a request look supported.
- The sources panel shows each channel's measured lossless capability -- available, unavailable, or not yet checked -- with a button to run the check on demand. A channel measured capable is preferred while `lossless_first` is in effect; a channel that has not been measured keeps exactly the position it had in `1.0.5`, so an unmeasured deployment orders channels as it always did.
- A channel that cannot answer a resolve at all is now a failed channel rather than an uncertain job: the download refreshes to another channel and re-prompts with a replacement, instead of being retried and dead-lettered.
- `best_available` is unchanged from `1.0.5`, with or without a configured preference.
- Synchronized main service, plugin runner, and web package versions at `1.0.6`.
- Both published images support the full deployment and Lite mode. Set `MUSICDL_IMAGE_TAG=1.0.6` to use them. The quick-install manifest now defaults to `1.0.6`.
- To roll back the image version, pin `MUSICDL_IMAGE_TAG=1.0.5` and follow the README backup and migration guidance.

## 中文

- `lossless_first` 现在会真正向音源索取无损。当策略为 `lossless_first`、而候选没有声明任何音质档位时（本部署的目录正是这样应答的），下载会直接请求 FLAC，而不再静默落到 `320k` 默认值。管理面板与企业微信消息两条链路都已接通。
- 请求的音质是"意图"，不是对音源的断言。下载报告把请求（`requested_quality`）与实际交付字节（`actual_quality`）分开记录；当无损请求被以更低音质应答时，面板会明确标出差距（"请求 flac，实际 mp3"）。音源没有真正交付的无损不会被记成无损，候选自身声明的档位也绝不会被改写来让请求看起来"被支持"。
- 音源面板会显示每个渠道实测的无损能力——可用 / 不可用 / 未检测——并提供按钮按需触发检测。在 `lossless_first` 下，实测可用的渠道会被优先选择；未检测的渠道保持 `1.0.5` 中原有的顺序，因此未做检测的部署，渠道排序与以前完全一致。
- 完全无法应答的渠道现在按"渠道失败"处理，而不是让任务变成 uncertain：下载会换源并重新提示替换，而不再重试到死信。
- `best_available` 与 `1.0.5` 完全一致，无论是否配置了偏好档位。
- 主服务、插件运行器和 Web 包版本统一为 `1.0.6`。
- 两份已发布镜像均支持完整部署和 Lite 模式。设置 `MUSICDL_IMAGE_TAG=1.0.6` 即可使用；快速安装清单现在默认使用 `1.0.6`。
- 如需回滚镜像版本，请固定 `MUSICDL_IMAGE_TAG=1.0.5`，并遵循 README 中的备份与迁移说明。
