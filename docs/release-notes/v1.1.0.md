# musicdl 1.1.0

## English

- Downloads from the administration panel and WeCom now leave persistent history, with outcomes, requested and actual quality, source attempts, fallback events, and failure details. The panel provides a paginated history and task timelines. Saved records survive service restarts; interrupted records do not imply automatic download resumption.
- Channel health now reports search availability, source download success, and lossless-quality fulfillment separately. These statistics use bounded windows within the current process and reset on restart; cancelled or local failures do not count against a source.
- Lossless-first source selection now uses download reliability conservatively after enough download samples are available, while retaining measured lossless capability and existing fallback safeguards. The best-available policy retains its existing selection behavior.
- Frontend CI now exercises service-log polling, search probes, source imports, and channel metric rendering. Structured release checks validate version metadata before publication and compare the published Release, both multi-platform image digests, source labels/provenance, and successful workflows afterward. Missing evidence is reported as unavailable, never as a pass.
- Main service, plugin runner, and web package versions are synchronized at `1.1.0`; quick install defaults to the `1.1.0` images. To roll back the image version, pin `MUSICDL_IMAGE_TAG=1.0.9` and follow the README backup and migration guidance.

## 中文

- 管理面板和企业微信下载现在会保留持久历史，记录结果、请求与实际音质、音源尝试、回退事件及失败详情。面板提供分页历史列表和任务时间线。已保存记录可在服务重启后查看；中断记录不代表下载会自动续传。
- 频道健康现在分别展示搜索可用率、来源下载成功率和无损音质兑现率。统计使用当前进程内的有界窗口，重启后重新累计；取消或本地原因导致的失败不计入音源失败。
- 无损优先选源现在会在下载样本充足后谨慎使用下载可靠性，同时保留已测得的无损能力和现有回退保障。best-available 策略保留原有选择行为。
- 前端 CI 现在覆盖服务日志轮询、搜索探测、来源导入和频道统计展示。结构化发布检查会在发布前核对版本元数据，发布后核对 Release、两个多平台镜像摘要、源码标签/provenance 和成功的工作流。缺少证据时报告无法验证，不会视为通过。
- 主服务、插件运行器和 Web 包版本统一为 `1.1.0`；快速安装默认使用 `1.1.0` 镜像。如需回滚镜像版本，请固定 `MUSICDL_IMAGE_TAG=1.0.9`，并遵循 README 中的备份与迁移说明。
