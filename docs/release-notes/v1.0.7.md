# musicdl 1.0.7

## English

- FLAC and MP4 downloads now receive bounded integrity checks of their audio data, catching truncated or inconsistent content that a valid container header could miss.
- Content errors can trigger up to three bounded channel switches across the panel and worker. Previously attempted sources are excluded; replacements favor healthy sources with cached lossless capability before recording duration. Download notices retain requested versus actual quality.
- Redis-backed WeCom selections now preserve an empty declared quality list, allowing workers to complete jobs for sources that do not report quality tiers.
- Synchronized main service, plugin runner, and web package versions at `1.0.7`.
- Both published images support the full deployment and Lite mode. Set `MUSICDL_IMAGE_TAG=1.0.7` to use them. The quick-install manifest now defaults to `1.0.7`.
- To roll back the image version, pin `MUSICDL_IMAGE_TAG=1.0.6` and follow the README backup and migration guidance.

## 中文

- FLAC 和 MP4 下载现在会对音频数据进行有界完整性检查，可发现仅凭有效容器头无法识别的截断或不一致内容。
- 内容错误会在管理面板和工作进程中触发最多三次有界音源切换。已尝试的音源会被排除；备用音源优先选择健康且具有缓存无损能力的渠道，再比较录音时长。下载通知保留请求与实际交付音质。
- 基于 Redis 的企业微信选曲现在会保留音源声明的空音质列表，使工作进程也能完成这类任务。
- 主服务、插件运行器和 Web 包版本统一为 `1.0.7`。
- 两份已发布镜像均支持完整部署和 Lite 模式。设置 `MUSICDL_IMAGE_TAG=1.0.7` 即可使用；快速安装清单现在默认使用 `1.0.7`。
- 如需回滚镜像版本，请固定 `MUSICDL_IMAGE_TAG=1.0.6`，并遵循 README 中的备份与迁移说明。
