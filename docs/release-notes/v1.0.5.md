# musicdl 1.0.5

## English

- A source's declared container, bitrate and size now reach the search results, the panel and the download report. A size the source only repeats from its own catalogue is treated as a reference: a body shorter than it is refused as an incomplete file, a longer body is accepted, and the download record, the panel report and the success message all carry the byte count the server actually sent.
- The search panel can show the container and size of each candidate before you download it. Resolve answers are the primary source for that size; the CDN is probed only when resolve states none. A probe tries `HEAD` first and falls back to a one-byte ranged `GET` when the CDN refuses `HEAD` or sends no `Content-Length`; the connection is closed as soon as the headers arrive, no body is read and no file is written. A probed size is shown only and never becomes a transfer contract.
- Channel selection now prefers a declared lossless tier. `MUSICDL_WORKER__QUALITY_POLICY` defaults to `lossless_first`; `best_available` restores the 1.0.4 behaviour, and `MUSICDL_WORKER__QUALITY_PREFERENCE` can name a tier to look for. A source that supports none of the preferred tiers is still used, so the preference never becomes an error.
- The download report names both the tier that was requested (`requested_quality`) and the tier the delivered bytes really are (`actual_quality`), and each record carries a `quality_revision` so a later, stricter verifier can identify records it no longer stands behind. A resolved URL carries its own lifetime; once it has expired the source is asked to resolve once more instead of streaming an address that was withdrawn.
- A 30-second preview, or a stream cut off half way, is no longer reported as a successful download when the catalogue states the track's length and the finished file can be measured. The file is measured in plain Python -- FLAC `STREAMINFO`, the MP3 frame chain, the MP4/M4A `mvhd` atom -- and refused as `incomplete_audio` when it falls outside the catalogue's duration by more than the tolerance. No ffmpeg, ffprobe or new dependency is involved.
- The new `media.verify_duration` setting controls that check. Whenever the length cannot be verified -- the file cannot be measured, or the source states no positive duration -- the download is accepted and the record carries `duration_unverified`. That is the `lenient` default, deliberately not upstream's, because many supplied lx sources state no duration at all and refusing them would break working downloads. `strict` refuses an unverifiable file instead. The refusal is a gate on publication: a file already in the library is measured and reported, but never refused or removed.
- On success the notice reports the bitrate the delivered bytes really carried, derived from the real byte count over the real playing time, and stays silent when it cannot be told.
- Synchronized main service, plugin runner, and web package versions at `1.0.5`.
- Both published images support the full deployment and Lite mode. Set `MUSICDL_IMAGE_TAG=1.0.5` to use them. The quick-install manifest now defaults to `1.0.5`.
- To roll back the image version, pin `MUSICDL_IMAGE_TAG=1.0.4` and follow the README backup and migration guidance.

## 中文

- 音源声明的容器、码率和大小现在会进入搜索结果、面板和下载报告。音源只是照抄自身目录的大小视为参考值：实际内容短于它按不完整文件拒收，长于它则接受，且下载记录、面板报告和成功消息一律使用服务器实际返回的字节数。
- 搜索面板可以在下载前显示每条候选的容器和大小。resolve 的返回值是大小信息的首选来源，只有 resolve 未给出大小时才探测 CDN。探测先发 `HEAD`，当 CDN 拒绝 `HEAD` 或没有 `Content-Length` 时回退为带 `Range: bytes=0-0` 的 `GET`；拿到响应头后立即关闭连接，不读取响应体、不写文件。探测到的大小仅用于展示，绝不会成为传输校验的契约。
- 频道选择现在优先声明支持无损的音质。`MUSICDL_WORKER__QUALITY_POLICY` 默认 `lossless_first`，`best_available` 恢复 1.0.4 的行为，`MUSICDL_WORKER__QUALITY_PREFERENCE` 可指定要寻找的音质。音源若都不支持所偏好的音质仍会照常使用，偏好不会变成失败。
- 下载报告同时给出请求的音质（`requested_quality`）和实际交付字节所属的音质（`actual_quality`），每条记录还带 `quality_revision`，以便将来更严格的校验逻辑能识别出自己不再认可的旧记录。解析出的 URL 会带上自身寿命；一旦过期就重新向音源解析，而不是继续硬试已失效的地址。
- 当目录给出了曲目时长、且成品文件能被测量时，30 秒试听片段或下到一半的流不再被报告为下载成功。文件由纯 Python 读取真实时长——FLAC 的 `STREAMINFO`、MP3 的帧链、MP4/M4A 的 `mvhd` 原子——超出目录时长容差时按 `incomplete_audio` 拒收。不涉及 ffmpeg、ffprobe 或任何新依赖。
- 新增设置 `media.verify_duration` 控制该校验。凡是时长无法验证的情况——文件测不出时长，或音源未给出正的时长——都放行下载并在记录中标注 `duration_unverified`。这是默认的 `lenient` 策略，刻意不同于上游：不少洛雪音源本就不提供时长，一律拒收会让这些音源全部失效。设为 `strict` 时改为拒收无法验证的文件。拒收只发生在交付之前：已在库中的文件只测量并报告，不会被再次拒收或删除。
- 成功提示会给出交付字节的真实码率，由真实体积除以真实播放时长推导；算不出时不显示。
- 主服务、插件运行器和 Web 包版本统一为 `1.0.5`。
- 两份已发布镜像均支持完整部署和 Lite 模式。设置 `MUSICDL_IMAGE_TAG=1.0.5` 即可使用；快速安装清单现在默认使用 `1.0.5`。
- 如需回滚镜像版本，请固定 `MUSICDL_IMAGE_TAG=1.0.4`，并遵循 README 中的备份与迁移说明。
